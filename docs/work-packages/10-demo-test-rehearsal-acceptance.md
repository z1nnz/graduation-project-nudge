# 10｜Demo 測試、排練與驗收

## 驗收觀念

本次不做量產可靠度，而是證明「指定比賽環境下可以穩定重播」。測試必須短、
可重現、能錄影，不要求萬用電表或 24 小時壓力測試。

## Gate A｜程式碼

每台都要：

- PlatformIO clean build 成功。
- warning 不包含明顯的記憶體越界或找不到 driver。
- Scene host test 通過。
- source 內有 build id 或 git short SHA。
- 沒有真實帳號、Token 或私人資料。

## Gate B｜最小顯示

每台都要：

- 紅、綠、藍、黑、白整屏顯示。
- 文字方向正確。
- 全螢幕範圍正常，沒有局部更新異常。
- 冷啟動 3 次。
- USB 拔插 3 次後仍可進畫面。

若圓屏或方屏在此 Gate 失敗，不接其他周邊。

## Gate C｜完整故事

- 8 個 Scene 按順序出現。
- Focus 動畫不阻塞輸入。
- Encouragement 不會永久停住。
- Complete 必定出現。
- Summary 能回 Home 或停留等待。
- Restart 從每一幕都能回 Boot。

## Gate D｜降級

在不接 App、關閉 Wi-Fi／手機藍牙時：

- Orbit 能自動完成整段。
- Station 能自動完成整段。
- 沒有等待 Cloud 的 loading。
- optional 模組錯誤只出現在 serial，不佔據主畫面。

## Gate E｜重播次數

| 測試 | 次數 | 通過條件 |
| --- | ---: | --- |
| Orbit 冷啟動 | 3 | 3/3 |
| Station 冷啟動 | 3 | 3/3 |
| Orbit 自動完整流程 | 10 | 10/10 |
| Station 自動完整流程 | 10 | 10/10 |
| Orbit Restart | 10 | 10/10 |
| Station Restart | 10 | 10/10 |
| 已採用的實體輸入 | 各 10 | 不重複觸發 |
| App／BLE（若採用） | 10 | 失敗時仍可本機展示 |

失敗要記錄 Scene、時間、版本與是否可重現。不是只寫「偶爾壞掉」。

## Gate F｜觀看品質

請非開發組員觀看，不先解釋程式：

- 5 秒內能找到主資訊。
- 30 秒內知道 Orbit 與 Station 的差異。
- 字體在實際桌面距離可讀。
- 完成動畫能被注意到。
- 不會把固定 Demo 資料誤認成真實即時資料。

至少收集兩位非開發者的一句回饋，必要時只調整文案、字級與節奏。

## 三次排練

### 排練 1｜工程排練

- 開 serial。
- 逐幕檢查。
- 找出 restart 與供電問題。

### 排練 2｜完整口頭排練

- 不看程式。
- 依 3 分鐘腳本。
- 計時。
- 拍攝一鏡到底。

### 排練 3｜故障排練

刻意：

- 不開 App。
- 關閉網路。
- 拔掉 P1 周邊。
- 讓其中一台先不上電。

展示者仍能用另一台與備援影片完成說明。

## 凍結規則

比賽前 3 天：

- 凍結 P0 韌體與 display driver。
- 只修會阻擋展示的 bug。
- 不新增感測器。
- 不重構共用架構。
- 不更新 library major version。
- 保存已驗收 binary 與 source commit。

比賽前 1 天：

- 只做燒錄、充電／供電、影片與線材確認。
- 不合併新功能 PR。

## 不可當作通過

- 只有 `[SUCCESS]` 燒錄畫面。
- 只有模擬器或電腦截圖。
- 只顯示一張靜態圖。
- 一定要連開發者手機或網路才能動。
- 只有開發者本人知道如何從故障恢復。
