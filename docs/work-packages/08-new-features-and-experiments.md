# 08｜新功能與產品實驗工作包

## 選擇原則

新功能要強化「低摩擦開始、同儕陪伴、可恢復的自律」，不能只增加頁數。每項
功能先做最小 tracer bullet，串過 UI、Cloud authority、Rules、privacy、測試與
量測，再決定是否擴大。

## 候選 1｜實體夥伴 Presence（優先）

### 假設

桌面裝置用角色動作、環境光燈效和一個旋鈕，可比手機通知更快讓使用者進入
下一個小行動。

### MVP

- ready 畫面顯示角色、下一個個人目標和最多三個允許房間。
- 旋鈕選情境，短按開始／暫停／繼續，長按完成。
- 燈效只表達裝置狀態和進度，不顯示另一人的私人狀態。
- 一個安全的 recovery cue：中斷後回來只顯示「從 5 分鐘重新開始」。

### 成功條件

至少 80% 測試使用者不看工程教學能開始一次活動；連線至 started Receipt 的
中位時間比從 App 多層導覽開始更短。先完成工作包 02、03 才可量測。

## 候選 2｜恢復儀式 Recovery Ritual（優先）

### MVP

- Cloud discipline identity 只根據最近證據提供一個可改變的 recovery state。
- App、Web、裝置提供同一個小選項：縮短、改時段、改活動；使用者自己確認。
- 完成後以角色／家庭樹／團體星球的柔和變化回應，不補扣歷史分數。

### 護欄

不稱人格、不預測疾病、不用羞辱文案、不自動改目標、不向家長或管理者揭露
個人的 recovery label。

## 候選 3｜接力式共同 Quest（第二階段）

### MVP

- 每人選擇自己的任務與時間，完成後點亮共同路徑的一段。
- 下一位成員可自由接力，沒有逾時懲罰；中斷時任何人可從新一輪接續。
- 只讀正式 Receipt 的布林／區間成果，不比較原始分鐘、步數或睡眠。

### 防濫用

manager 不能代接力；同一 Receipt 不能重複點亮；退出／撤回分享立即影響未來
可見性。個人 coin/XP 仍只由 Reward Ledger 結算一次。

## 候選 4｜可撤回的成果卡（第二階段）

把一段已驗證成果生成最小分享卡：活動類型、日期區間、角色／共同世界變化，
不含精確健康值、原始 Ledger 或永久 recovery label。分享為 opt-in、有期限、可
撤回的 projection，不直接公開私人 snapshot。

## 候選 5｜情境式下一步建議（P2）

先用透明規則，後用模型實驗：

1. 只從已同意且必要的近期 aggregate 產生最多三個建議。
2. 每個建議顯示原因和可關閉控制。
3. 任何建議由使用者確認後才建立任務。
4. 模型不得寫 Ledger、改 coin/XP、改 Membership、替他人控制活動。
5. 若未來做預測，先完成資料 minimization、bias/錯誤分析與大量使用者分片架構。

## 實驗卡格式

每個新功能在開發前補齊：

```text
問題：
目標使用者／情境：
一句假設：
最小切片：
正式資料來源：
使用者同意／撤回：
主要指標：
護欄指標：
停止條件：
不做範圍：
```

## 優先順序

1. 先完成實體夥伴 Presence，因為它直接使用已投資的硬體與 Ledger。
2. 再做 Recovery Ritual，凸顯「中斷也能回來」的差異。
3. 再以小規模接力 Quest 驗證同儕誘因。
4. 成果卡與 AI 建議只有在 consent、稽核、量測成熟後開發。

不要同時開發五項；每次只准一個實驗進入 build，其餘維持 proposal。
