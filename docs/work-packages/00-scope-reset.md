# 00｜工作範圍重設：只做競賽 Demo

## 決策

本工作包的輸出不是商品，也不是實驗室級硬體驗證，而是可在專題競賽桌面上
穩定演示的雙裝置原型。所有人以「看得見、講得懂、能重播」為優先。

## 一句話產品故事

Nudge 把 App 裡抽象的自律進度變成身邊看得見的角色與環境回應：Orbit 跟著
個人移動，Station 留在桌面陪伴專注；完成行動後，兩台裝置用一致的角色和
光影回應使用者。

## P0 必做

- 兩片已購買的 ESP32 與螢幕都能被各自燒錄。
- 每台都有開機、首頁、開始、進行、完成、角色成果至少 6 個場景。
- 自動 Demo 不依賴網路、Firebase、手機、登入或感測器。
- 操作者可在 3 分鐘內展示兩台裝置的差異與共同價值。
- 每台皆有可重播的 Reset Demo 動作。
- 交付 source、binary、燒錄命令、影片與簡短故障備援。

## P1 有時間才做

- 現有觸控、按鍵或旋鈕切換場景。
- 現有 LED 顯示專注進度或完成效果。
- 現有光感調整亮度。
- 現有蜂鳴器播放低音量開始／完成提示。
- 讓兩台裝置共享同一套顏色、角色與文案常數。

任何 P1 模組初始化失敗時都必須略過，不能造成螢幕停在白屏。

## P2 可明確不做

- App 透過 BLE 控制裝置。
- App 與兩台裝置同步同一個 session。
- 真實家庭／團體／自律房資料。
- Cloud Receipt、獎勵與正式帳號。

P2 只有在 P0 已凍結、兩台都通過 10 次重播後才能開始。

## 這次不需要

- 新購萬用電表、烙鐵、洞洞板、示波器或邏輯分析儀。
- 焊接展示成品或永久固定線路。
- 加裝電池與充電板。
- 量測溫升、電流或做長時間可靠度報告。
- 為未知模組猜測 GPIO 或供電。
- 把所有 App／Web／Cloud 未完成項目一起塞給硬體組員。

## 「燒錄」仍然必要

螢幕不會自己顯示 Nudge 畫面。組員仍需要用 PlatformIO 把 Demo 韌體上傳到
XIAO ESP32S3。這個動作可重複、可更新，不等同量產寫死：

```sh
pio run --project-dir firmware/nudge_focus_device
pio run --project-dir firmware/nudge_focus_device --target upload
pio device monitor --baud 115200
```

每台裝置在燒錄前要確認目前選到的 serial port，不能同時接兩台後靠猜測。

## 展示資料的誠實邊界

| 畫面內容 | 可以怎麼說 | 不可以怎麼說 |
| --- | --- | --- |
| 韌體內固定任務 | 「這是原型展示資料」 | 「這是教授帳號的即時任務」 |
| 自動輪播的家庭訊息 | 「展示家庭鼓勵在裝置上的呈現」 | 「目前已從家長端即時同步」 |
| 固定角色 XP | 「示範任務完成後的角色回應」 | 「Cloud 已正式核發 XP」 |
| 真實按鍵觸發 | 「按鍵真的控制裝置場景」 | 不需誇大 |
| 真實 BLE 連動 | 「App 已透過 BLE 觸發」 | 若只是假資料，不得稱完整 Cloud 同步 |

## 範圍變更門檻

任何人提出新功能前，必須回答：

1. 是否使用已購買零件？
2. 是否能在一天內完成並回復？
3. 是否不影響兩台 P0？
4. 評審是否能在 30 秒內看懂差異？
5. 失敗時是否能自動降級？

五項中只要一項為否，就排到比賽後。

## 完成定義

這份範圍重設完成，不是指大家讀過，而是：

- 所有開放中的硬體 Issue 已標記 P0／P1／P2。
- 舊工作包連結與舊 ZIP 被標記 superseded。
- 兩位組員的 PR 描述引用本文件。
- 新增需求不再以「正式產品會需要」作為競賽前必做理由。
