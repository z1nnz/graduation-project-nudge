# Nudge 夥伴小屋與休息小遊戲：App 與 Web 遊戲化改版設計

日期：2026-11-23。決策人：@z1nnz（方向與取捨），Claude（標為「Claude 決定」的細節）。
對應工作包：C（角色生活空間）與 D（共同世界）。本設計取代兩包原本以卡片版面為主的呈現方式，但不改變它們的資料與權限規則。

## 為什麼要改

初賽評審認為 Nudge 的遊戲化與獎勵機制概念很好，但「還不夠吸引人」。現在的 App 與 Web 功能齊全，可是看起來像儀表板：Web 首頁標題是「自律宇宙控制台」，左側是功能選單，畫面主體是一張張資料卡片。另外，角色升級目前只是數字變大，沒有「升級之後能做什麼」。

目標感受（使用者原話）：評審拿起 App 的第一分鐘覺得「哇，這個 App 看起來好厲害」，介面本身就能吸引人；實際用起來也真的好玩。

## 目標

- 打開 App 或 Web 第一眼是角色住的小屋，不是資料卡片。
- 房間會隨 Cloud 確認的真實成果長大，成長看得見。
- 角色等級有意義：等級越高，休息時間能玩的小遊戲越多。
- App、Web、Orbit／Station 硬體屬於同一個世界觀，專題簡介的圖像一致。

## 非目標

- 不新增金幣或經驗值來源，不改獎勵公式、Cloud Ledger、Rules 或權限。
- 不做開放世界、多人即時同屏或付費內容。
- 不重畫角色。

## 反目標（做到這些就算失敗）

- 慶祝動畫在 Cloud 確認前播放，或顯示推算出來的獎勵。
- 小遊戲能賺金幣或經驗值，讓人靠玩遊戲升級。
- 小遊戲可以無限制地玩，讓 Nudge 變成分心工具。
- 使用者找不到原本的功能入口（家庭、團體、隱私、設定）。
- 畫風割裂：3D 場景配像素角色，或直接沿用其他作品的成品素材。

## 已否決的方向

- 「浮島冒險」與「星空浮島」：做出概念圖後，使用者認為 3D 浮島配像素角色很突兀。
- 「星球育成」：「下一步」不夠直覺。

## 美術方向（Claude 決定）

- 全部採像素風，解析度與現有角色一致。房間、家具、介面框線都是像素風，App 與 Web 共用同一套素材。
- 素材由 AI 產圖（Codex CLI 影像生成）加程式整理成像素格與透明背景，存放於 `assets/home/`；Web 複製或引用同一份檔案。
- 窗外依裝置本地時間顯示白天、黃昏、夜晚三種景色。

## 畫面結構

### 1. 首頁「夥伴小屋」（App 與 Web）
- 角色以現有像素素材顯示，在房間內小範圍走動、待機；點擊有表情與對話回應。
- 對話泡泡沿用 DailyNextAction，只給一個主要行動。
- 牆上的委託板列出今天的任務（沿用現有任務資料）。點委託單進入既有的專注或任務流程，不建立新的活動來源。
- 頂部 HUD：等級、經驗條、金幣、連續天數，讀取現有 AppState 與 Web 投影。

### 2. 房間成長（只讀 Cloud 確認的資料；Claude 決定對應方式）
| 房間物件 | 依據的現有資料 | 呈現 |
|---|---|---|
| 書櫃上的書 | 已確認的專注／讀書次數 | 數量分段增加 |
| 窗邊盆栽 | 連續天數 | 越久越茂盛；中斷會枯一點，不會消失 |
| 牆上徽章框 | 現有徽章 | 取得的徽章掛上牆 |
| 桌上地球儀與小燈 | Orbit／Station 裝置綁定與狀態 | 綁定後出現，專注中發光 |
| 角色外觀 | 現有角色階段與裝備 | 直接顯示目前裝備 |

只有 ConfirmedActivityFeedback 回報新的 Cloud 確認時，才播放「新物件出現」的動畫。pending 只顯示「等待確認」的提示，不顯示數字。

### 3. 房門通往同伴（D 包）
一扇門通往家庭庭院，另一扇通往團體交誼廳，分別進入現有家庭與團體頁面，只顯示合法可見的摘要，沿用既有身分與同意規則。

### 4. 休息小遊戲（Web／PWA）
- **取得休息時間**：每完成一次 Cloud 確認的專注，得到一張休息券。專注 25 分鐘以上給 5 分鐘，50 分鐘以上給 10 分鐘。休息券在確認後 2 小時內有效，不能累積超過 2 張。
- **使用**：在 Web 的小屋點「休息時間」開始倒數，帶角色進入小遊戲。時間到時角色提醒回到下一個委託，遊戲暫停並結算。
- **等級解鎖**（Claude 決定，三款皆為通用玩法，不仿製特定遊戲）：
  - Lv1「接星星」：角色左右移動接住落下的星星，躲開烏雲。
  - Lv5「記憶翻牌」：翻出成對的任務圖示。
  - Lv10「節奏專注」：跟著節拍點擊，連擊越長分數越高。
  - 更高等級解鎖既有遊戲的新關卡或難度。
- **不影響正式獎勵**：遊戲分數不給金幣或經驗值，只解鎖遊戲內的紀念物（例如小屋裡的獎盃架）。
- **資料**：休息券由已確認的專注紀錄推導，不新增 Cloud 寫入。已使用的休息券與遊戲紀錄存在本機，以帳號隔離；換帳號不會沿用。這只影響休閒內容，不涉及正式獎勵，本機保存可以接受。
- App 端顯示「休息券」與「到 Web 玩」的入口；第一版小遊戲只做在 Web。

### 5. 原有功能
底部導覽四個入口：小屋、委託、圖鑑、同伴。其餘功能（統計、隱私、設定、裝置）收進「背包」選單，不刪除任何現有頁面。

## 呈現與技術（Claude 決定）

- App：Flutter 以圖層方式組合房間（背景、家具、角色、特效），角色動畫用精靈圖切格。不加入遊戲引擎套件。
- Web：純 HTML、CSS 與 Canvas，小遊戲各自是獨立 ES 模組，只在休息時間載入。
- 新元件以 presentation model 讀取既有 AppState 與 Web 現有腳本，不修改 `app_state.dart`、`app.js` 的資料邏輯。需要新介面時依 PR #70 的規則交 A 協調。

## 交付順序

1. 像素小屋概念圖（確認風格）。
2. 房間與家具素材、角色待機與走動動畫。
3. App 首頁「夥伴小屋」，包含房間成長與確認回饋。
4. Web／PWA 首頁「夥伴小屋」。
5. 休息券與三款小遊戲（Web）。
6. 房門通往同伴（家庭、團體），對接 D 包。
7. 專題簡介用圖：系統架構、App 畫面、韌體畫面。

## 驗收

- C 包與 D 包原有的驗收矩陣全部適用：未登入、無任務、pending、cache、錯誤、帳號切換、360px、深色、減少動態。
- 休息券：只有 Cloud 確認的專注能產生；超過有效期或上限不能使用；換帳號不沿用；倒數結束後遊戲停止。
- 小遊戲不呼叫任何獎勵或 Ledger API（以測試確認）。
- 中階 Android 實機首頁維持流暢；首頁冷啟動到可操作不超過 3 秒。
- 每個畫面附實際截圖；不得把概念圖當成已實作畫面。

## 留給實作者決定

- 動畫影格數、粒子數量、各解析度尺寸。
- 委託板在任務數 0／1／超過 6 個時的排版。
- 小遊戲的細部難度曲線。
