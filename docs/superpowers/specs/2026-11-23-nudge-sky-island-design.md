# Nudge 星空浮島：App 與 Web 遊戲化改版設計

日期：2026-11-23。決策人：@z1nnz（方向與取捨），Claude（標為「Claude 決定」的細節）。
對應工作包：C（角色生活空間）與 D（共同世界）。本設計取代兩包原本以卡片版面為主的呈現方式，但不改變它們的資料與權限規則。

## 為什麼要改

初賽評審認為 Nudge 的遊戲化與獎勵機制概念很好，但「還不夠吸引人」。現在的 App 與 Web 功能齊全，可是看起來像儀表板：Web 首頁標題是「自律宇宙控制台」，左側是功能選單，畫面主體是一張張資料卡片。

目標感受（使用者原話）：評審拿起 App 的第一分鐘覺得「哇，這個 App 看起來好厲害」，介面本身就能吸引人；實際用起來也真的好玩。

## 目標

- 打開 App 第一眼就是一個遊戲世界，不是資料卡片。
- 每天的任務變成看得見的冒險路線，有「下一站」可以期待。
- 角色與世界會隨 Cloud 確認的真實行動成長，而且成長看得見。
- App、Web、Orbit／Station 硬體屬於同一個世界觀，放進專題簡介時圖像一致。

## 非目標

- 不新增獎勵種類、不改金幣與經驗值公式、不改 Cloud Ledger、Rules 或權限。
- 不做開放世界移動、戰鬥系統或多人即時同屏。
- 不重畫角色。

## 反目標（做到這些就算失敗）

- 慶祝動畫在 Cloud 確認前就播放，或顯示推算出來的獎勵。
- 遊戲畫面讓使用者找不到原本的功能入口（家庭、團體、隱私、設定）。
- 為了特效讓中低階 Android 手機掉到明顯卡頓。
- 直接搬用 Elder Tree ESG 的成品，與 Nudge 品牌產生割裂感。

## 美術方向：「Nudge 星空浮島」

- **配色**來自 Nudge 圖示：紫藍漸層夜空、金色星光；時間設定在黃昏到入夜。
- **主島**是使用者與角色的家。中央是「星願樹」：結出發光的星星果實，每一顆代表一筆 Cloud 確認的行動。
- **星願樹有 6 個生長階段**：種子、發芽、幼苗、小樹、成樹、大樹。依已確認的累積成果前進，門檻沿用 B 包公開的角色成長資料，不在前端另訂公式。若 B 尚未提供，以已確認行動天數暫代並標示為暫定。
- **角色**維持現有像素 Q 版素材，以 2D 精靈站在 3D 場景中。
- **硬體進入世界**：Orbit 是繞主島運行的小月亮，Station 是島上的燈塔。綁定的裝置在線或專注中時，對應物件會發光。
- **來源**：沿用 Elder Tree ESG（GitHub `z1nnz/elder-tree-esg`，`tools/blender/build_life_tree.py`）的浮島與樹建模方法與骨架。以 Nudge 配色和星願樹造型重新產生，不直接使用該作品的渲染圖或貼圖。

## 呈現方式（Approaches）

| 方式 | 內容 | 取捨 |
|---|---|---|
| 全 3D 即時 | 整個世界在 App／Web 即時渲染、可旋轉 | 震撼感最強；模型需大幅壓縮，舊手機易卡，工作量最大 |
| 2.5D 預渲染 | Blender 算圖，App／Web 用多層視差與動畫組成 | 各裝置流暢、畫質穩定；無法轉動視角 |
| **混合（採用）** | 首頁主島用壓縮後的 3D 模型可旋轉；地圖與其他畫面用 2.5D 圖層 | 第一分鐘的「哇」來自可轉動的主島，日常操作維持流暢 |

使用者把呈現方式交給 Claude 決定，Claude 選「混合」。

## 畫面結構

1. **首頁「我的浮島」**（App 與 Web 共用設計）
   - 3D 主島：星願樹、角色、Orbit 月亮、Station 燈塔。可拖曳旋轉，減少動態設定開啟時改為靜態圖。
   - 頂部 HUD：等級、經驗條、金幣、連續天數，資料來自現有 AppState。
   - 角色對話泡泡：沿用 DailyNextAction，只給一個主要行動。
   - 主按鈕「出發冒險」：進入今日路線。
2. **今日冒險路線**
   - 今天的任務依序排在一條跨越小浮島的路線上：已完成、目前、未開始。週目標是盡頭的「頭目島」。
   - 點目前站點：開始對應的既有流程（專注計時、任務完成等），不建立新的活動來源。
3. **確認回饋**
   - 只有在 ConfirmedActivityFeedback 回報新的 Cloud 確認時，才播放星星果實落入樹上、金幣與經驗值跳出的動畫。
   - pending 狀態顯示「等待確認」的光點，不顯示數字。
4. **同伴群島**（D 包）
   - 家庭樹島、團體星球島以相鄰浮島呈現，只顯示目前合法可見的摘要；點進去沿用既有家庭／團體頁面與身分規則。
5. **原有功能**
   - 底部導覽保留四個入口：浮島、冒險、圖鑑、同伴。
   - 其餘功能（統計、隱私、設定、裝置）收進「背包／選單」，不刪除任何現有頁面。

Web 版是同一個世界的大螢幕版本：左側浮島與路線、右側當前行動與回饋，可安裝為 PWA（沿用 #69）。

## 技術決定（Claude 決定）

- 3D 主島模型：在 Blender 產生後以 glTF 匯出，經 meshopt 或 Draco 壓縮，目標 3 MB 以內。
- App 端 3D 檢視：先評估 `flutter_scene` 與 WebView 型的 `model_viewer_plus`，以中階 Android 實機幀率決定。若都無法穩定 30 fps，主島退回預渲染的 360° 序列圖（拖曳時切換角度）。
- Web 端 3D：three.js，於首頁按需載入，不影響其他頁面。
- 2.5D 圖層：Blender 渲染 PNG／WebP，依螢幕寬度提供 2 種解析度。
- 所有新元件以 presentation model 讀取既有 AppState 與 Web 現有腳本。不修改 `app_state.dart`、`app.js` 的資料邏輯；需要新介面時依 PR #70 的規則交 A 協調。

## 交付順序

1. 概念圖：Nudge 星空浮島主視覺，用來確認風格（本設計核准後的第一步）。
2. 3D 主島與 6 階段星願樹模型、2.5D 圖層素材。
3. App 首頁「我的浮島」與確認回饋動畫。
4. App 今日冒險路線。
5. Web／PWA 首頁與路線。
6. 同伴群島（家庭、團體），對接 D 包。
7. 專題簡介用圖：系統架構、App 畫面、韌體畫面。

## 驗收

- C 包與 D 包原有的驗收矩陣全部適用：未登入、無任務、pending、cache、錯誤、帳號切換、360px、深色、減少動態。
- 中階 Android 實機首頁維持 30 fps 以上；首頁冷啟動到可操作不超過 3 秒。
- 每個畫面附實際截圖；不得把概念圖當成已實作畫面。

## 留給實作者決定

- 動畫曲線、粒子數量、各解析度的確切尺寸。
- 冒險路線在任務數 0／1／超過 6 個時的排版。
- 星願樹各階段的造型細節：維持同一棵樹逐步長大的連續感即可。
