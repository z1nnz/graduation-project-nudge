Nudge 系統地圖

一張圖分清楚電力、控制、資料與信任。遇到問題時，先判斷它落在哪一層。

四條不同的「流」

電力流5V/2A → XIAO／圓屏／LED；XIAO 3.3V → Qwiic 模組。所有模組共地。
控制流旋鈕／App 指令 → ESP32 狀態機 → 螢幕、LED、蜂鳴器。
活動資料流ESP32 durable queue → BLE → App durable outbox → Cloud Activity Ledger。
授權流Web 管理員建立 DeviceAssignment；App 每次控制與上傳前重新驗證。

資料流

Web 管理後台→ Cloud DeviceAssignment→ Android App⇄ BLE ESP32 韌體→ App Outbox→ Cloud Ledger

信任邊界：ESP32 只回報「發生了什麼」，不能直接加 XP、改角色或授予家庭／團體權限。Cloud 才是正式資料的裁決者。

硬體介面

SPI高速、通常一主多從。圓屏像「快速影像管線」，由 SCK/MOSI/MISO 與個別 CS 控制。
I²C / Qwiic兩條資料線 SDA/SCL，多模組靠不同位址共用。VEML7700 0x10、Buzzer 0x34、Encoder 0x36。
PWM快速切換高低電位，用占空比形成平均亮度。Round Display 的 D6 是否穩定可調要真機驗證。
BLE GATTService 像功能區，Characteristic 像欄位。App write 指令、read 事件、subscribe state notify。
NVSESP32 斷電仍保留的小型儲存。保存裝置畫面 context、sequence 與未 ACK 事件。
Level shiftingESP32 資料為 3.3V，5V WS2813 需要 AHCT/HCT 把高準位提升到規格安全範圍。

上電前五問

  1. 這個模組要吃 5V 還是 3.3V？
  2. 它的訊號邏輯電壓是多少？
  3. 所有電源是否共用 GND？
  4. 5V 與 GND 間是否意外短路？
  5. 今天只新增了哪一個變因？失敗時能否拔掉它回到上一個成功狀態？
